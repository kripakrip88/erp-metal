# GitHub & Server Rules

## Работа с ветками
- Никогда не пушить напрямую в main
- Всегда создавать отдельную ветку: feature/..., fix/..., refactor/...
- Перед PR показать список изменений, риски, что тестировалось

## Перед любыми изменениями
1. Прочитать связанные файлы
2. Показать план изменений
3. Ждать подтверждения

## Сервер
- Разрешено: читать логи, docker ps/logs, перезапускать dev сервисы
- Запрещено: менять firewall, SSH, удалять системные файлы, чистить базу

## База данных
- Запрещено: DROP, массовое удаление, деструктивные миграции
- Разрешено: чтение схемы, безопасные миграции, backup перед изменениями

## Безопасность
- Никогда не выводить токены, пароли, SSH keys, .env содержимое

## Decision Making
- Всегда предлагать два варианта: простой и сложный
- Руководитель выбирает направление исходя из перспективы

## Главный принцип
Стабильность ERP и безопасность данных важнее скорости изменений.
