## Этап 1 — Файловая платформа

**Цель:** прикреплять PDF/DXF/STEP/XLSX к заказам прямо в ERP.

### Новые файлы

| Файл | Что делает |
|------|------------|
| `src/services/storageService.js` | Локальное хранилище: `upload()`, `getStorageUrl()`, `deleteStoredFile()`. Директория из env `UPLOADS_DIR` или `./uploads/` |
| `src/utils/parseMultipart.js` | Парсер multipart/form-data через `busboy`. Исправлена race condition между busboy `finish` и fs.WriteStream `finish` через два флага `bbDone`/`writerDone` + `tryResolve()` |
| `src/routes/files.js` | Три endpoint'а ниже |

### API файлов

```
POST   /api/orders/:id/files    — загрузить файл к заказу (ENGINEER+)
GET    /api/orders/:id/files    — список файлов заказа
DELETE /api/files/:id           — мягкое удаление (ADMIN)
```

Физически файлы хранятся в `./uploads/<uuid>_<filename>`.  
URL отдаётся как `/uploads/<uuid>_<filename>` — отдаётся напрямую сервером без авторизации (UUID как security-by-obscurity).

### Изменения в UI (simulator.html)

- Кнопка **📎 Документы** с бейджем счётчика в панели действий заказа
- Страница `page-files` — загрузка файла + таблица прикреплённых файлов
- Вкладка **📎 Файлы** в правой панели заказа (рядом с Узлами / Сортаментом / Ревизиями)
- Функции: `loadFiles()`, `uploadFile()`, `renderFiles()`, `renderRpFiles()`, `formatFileSize()`

### Ключевые исправления

| Ошибка | Причина | Исправление |
|--------|---------|-------------|
| `TypeError: Do not know how to serialize a BigInt` | Prisma возвращает `sizeBytes` как BigInt | Глобальный replacer в `response.js` |
| `No file provided` | Race condition в busboy | Два флага + `tryResolve()` |
| Файл загружен, но не появляется в списке | `include: { file: { where: {...} } }` — невалидный синтаксис для to-one relation в Prisma | Убран `where` из include, фильтр перенесён в JS |

## Вариант В — Email → ERP (Create RFQ)

**Цель:** кнопка "Создать RFQ" в почте создаёт реальный заказ ERP + клиента в CRM.

### Архитектурные решения (9 замечаний от GPT-review)

| # | Проблема | Решение |
|---|----------|---------|
| 1 | Плохое название endpoint | `POST /api/orders/from-email` |
| 2 | Логика в route | Отдельный `createOrderFromEmailService.js` |
| 3 | Нет идемпотентности | Проверка `Interaction.emailMessageId @unique` перед созданием |
| 4 | Доверять `extractedCompany` от AI нельзя | Клиент ищется только по `fromAddress` |
| 5 | Нет нормализации email | `normalizeEmail()` — lowercase + trim |
| 6 | Хранить только messageId — мало | Interaction хранит: subject, body с From/Subject |
| 7 | Нет транзакции | `prisma.$transaction()` для customer + order + interaction |
| 8 | Frontend знает слишком много | Передаёт только `{ messageId, title, fromAddress, fromName, subject }` |
| 9 | Нет event architecture | Пишет `OutboxEvent` типа `RFQ_CREATED_FROM_EMAIL` |

### Новые файлы

| Файл | Что делает |
|------|------------|
| `src/services/createOrderFromEmailService.js` | Вся логика: normalize → idempotency → transaction(find/create customer → create DRAFT order → create INBOUND Interaction → OutboxEvent) |
| `src/routes/ordersFromEmail.js` | `POST /api/orders/from-email`, MANAGER+, валидирует messageId + fromAddress |

### Изменения в UI (email-inbox.html)

Функция `createRfqFromEmail(id)`:
- Вызывает ERP `/api/orders/from-email` (раньше вызывала AI-сервис на порту 4000)
- Передаёт `{ messageId, title, fromAddress, fromName, subject }` (без `extractedCompany`)
- Показывает `"Заказ создан: RFQ-..."` или `"Заказ уже существует"` при повторном нажатии
- Предлагает открыть заказ в simulator.html

### Поток данных

```
email-inbox.html
    │
    └── POST /api/orders/from-email
              │
              ├── normalizeEmail(fromAddress)
              ├── Idempotency: Interaction.findUnique(emailMessageId) → если есть → return
              └── prisma.$transaction:
                    ├── Customer.findFirst(email) → если нет → Customer.create
                    ├── Order.create(status: DRAFT, customerId)
                    ├── Interaction.create(type: EMAIL, direction: INBOUND, emailMessageId)
                    └── OutboxEvent.create(RFQ_CREATED_FROM_EMAIL)
```

## Вариант Б — Лог ответов + авто-переход заказа в КП

**Цель:** когда менеджер отвечает на письмо → в CRM логируется исходящее взаимодействие, заказ автоматически переходит DRAFT → QUOTATION.

### Новые файлы

| Файл | Что делает |
|------|------------|
| `src/routes/emailCopilot.js` | `POST /api/email-copilot/log-reply`, MANAGER+ |

### Логика endpoint `POST /api/email-copilot/log-reply`

```
Body: { messageId, replyBody, subject }

1. Interaction.findUnique(emailMessageId) → ищем оригинальное входящее письмо
2. Если не найдено → logged: false (письмо без RFQ — ок, без ошибки)
3. prisma.$transaction:
   a. Interaction.create(type: EMAIL, direction: OUTBOUND, customerId, orderId)
   b. Если order.status === 'DRAFT' → Order.update(status: 'QUOTATION')
4. Return { logged, interactionId, orderId, orderNumber, statusChanged }
```

### Изменения в UI (email-inbox.html)

Функция `sendReply()`:
- После успеха AI-сервиса (`/api/email-copilot/reply`) → вызывает ERP `/api/email-copilot/log-reply`
- Вызов ERP — **best-effort**: ошибка ERP не блокирует отправку письма
- Если `statusChanged === true` → показывает toast `"Заказ RFQ-XXX переведён в КП"`

## Итоговый статус интеграции Email ↔ ERP

```
Письмо в inbox
    │
    ├── [AI-сервис, порт 4000] — IMAP, Claude AI-анализ, черновики ответов
    │
    └── [ERP, порт 3000]
            ├── "Создать RFQ" → Customer + DRAFT Order + INBOUND Interaction
            └── "Отправить ответ" → OUTBOUND Interaction + DRAFT→QUOTATION
```
